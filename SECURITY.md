# Security

quota-board reads AI subscription logins that are already on your machine. This page says exactly what it does with them.

## What it reads and where it sends it

| Provider | Reads (read-only) | Sends it to |
|---|---|---|
| Claude | `~/.claude/.credentials.json`, or the macOS keychain item Claude Code uses | `api.anthropic.com`. If that fails, it runs `claude -p /usage` and `claude auth status --json` (only the plan tier is kept) and Claude Code makes the request itself. |
| ChatGPT / Codex | `~/.codex/auth.json` | `chatgpt.com`. If that fails, it asks Codex through `codex app-server` and Codex makes the request itself; if that fails too, it reads the newest `~/.codex/sessions` logs. Those logs contain your conversations; only the line recording your rate limits is used. |
| Cursor | Cursor's local `state.vscdb` (sign-in token), turned into the cursor.com login cookie for one request | `cursor.com` |
| Google Antigravity | runs `agy -p /usage --output-format json`; falls back to Antigravity's local `state.vscdb` cache | nothing; `agy` talks to Google itself |
| OpenCode Go | `~/.local/share/opencode/auth.json`, or `OPENCODE_GO_API_KEY` | `opencode.ai` |

- `CLAUDE_OAUTH_TOKEN` and `CURSOR_ACCESS_TOKEN`, if set, are used instead of the files above.
- Logins are opened read-only. quota-board never refreshes, rotates or rewrites them. (When it asks Claude Code or Codex instead, those tools may refresh their own logins, as they do whenever you use them.)
- `QUOTA_BOARD_DIRECT=0` turns off every row's file reading except OpenCode's key: Claude and Codex are then read only through their own tools, and Cursor isn't checked.
- Running `claude -p /usage` never sends a prompt: Claude Code answers it locally and reports zero turns. If a future Claude Code ever sent it to the model instead, quota-board detects that from the turn count, turns the fallback off, and says so.
- Each login goes only to that provider's own API.
- There is no telemetry and no other network traffic. `quota-board report` only prints a link for you to open.
- The one-line command downloads `dist/quota-board.mjs` from this repository over HTTPS each time it runs. That file is generated by CI from the source in this repository; you can read it, or run from a clone instead.

## What it stores

In `~/.quota-board` (or `QUOTA_BOARD_HOME`), created readable only by your user account:

- `config.json`: your plan choices, prices and hand-entered readings
- `last.json`: the last collection (percentages, reset times, tier names, counts)
- `dashboard.html`: the dashboard snapshot
- `cache/<hash>/`: the unpacked single-file edition (code and plan files only)

None of them contain tokens, emails or account ids.

## The local server

`quota-board serve` listens on `127.0.0.1` only. It rejects requests whose `Host` isn't localhost (against DNS rebinding), requires a custom header on every write (against cross-site requests), and sends a restrictive Content-Security-Policy.

## Reporting a vulnerability

Please don't open a public issue. Use GitHub's private reporting: the repository's **Security** tab, then **Report a vulnerability**. Include what you found and how to reproduce it. You'll get a reply within a week.

Especially welcome: any way quota-board could leak a token, send data anywhere other than the provider's own API, or let a web page read the local server.
